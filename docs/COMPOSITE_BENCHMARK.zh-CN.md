# HydroTune 组合任务与技能对照评测

本次增加 24 道组合题：数据处理 8、模型计算 12、结果分析 4，其中正常交付
20、科学阻断 4。183 道原子题保持独立，原子覆盖仍为 41/41；全量定义为
207 道。任务目录位于 `composite_tests/`，逐题矩阵见
[本地报告生成与资源准备](EXTERNAL_RESOURCES.md)。

设计参考 [BioTaskBench](https://github.com/GPTomics/bioTaskBench) 的多步骤任务、
本地可复现资料和确定性成果评分，补充水文科学闸门及必要信息确认。
正常题均有至少三个不同的核心科学能力和真实成果依赖。报告、图册、确认、
同一方法的重复执行不计入最低能力数。评分检查成果，允许等价实现。

## 发布与验收边界

仓库提供任务、资料、隐藏参考、评分器、确认接口、CLI 事件适配器和调度代码；运行结果与宿主机认证不随仓库分发。完整复现须另外准备程序、技能、原始资料和容器，并在本机重新认证。正式入口拒绝未冻结或未认证的配置，参考计算通过也不能作为 Agent 成功率。准备步骤见[外部资源说明](EXTERNAL_RESOURCES.md)。

## 数据与科学契约

原始输入只读来自用户指定的两套 `input` 目录。来源文件哈希在
`composite_assets/source_manifest.json`，逐项补充值及来源副本随每道题提供。
集总资料含 48 场、4,976 行；半分布式资料为 2006—2025 年连续记录。
组合题采用代表性场次及 2023 年 8 月短窗口，连续 XAJ 和连续率定采用
8 月 15—18 日的 96 小时窗口。

原始降雨空白仍保存在 `original.csv`／`original_events/`。正常题的测试
补充明确标为合成值，保留已知实测值及逐项补充记录；不宣称修复真实观测。
时区、断面、蒸散映射、参数和外部入流关系缺少资料证据时，作为测试场景
设定或必要确认项处理。`scenario.json` 是可见的测试配置，不提供任务解法。

空间案例保留真实边界，采用 100 m 米制网格和明确设定的 100 km² 起始面积。
独立 QC 检验拓扑引用、栅格、面积、覆盖与出口。较小起始面积产生的微小
孤立单元未作为半分布式正常输入，也没有篡改拓扑或降低 QC 标准。
WhiteboxTools 固定 `max_procs=1`，避免其多线程填洼输出的重复性漂移。
详细差异见[本地报告生成与资源准备](EXTERNAL_RESOURCES.md)。

洪水识别采用当前 1.2 雨量支持契约，检查面平均雨量、回溯期、雨量阈值和
无雨／全缺失事件策略。保留事件不等于事件及预热期 forcing 完整。D02
对未授权解决的缺测进行阻断。D08 检验确认出口数与真实结构冲突；M10
阻断不稳定演算配置；A04 复核实际评分时间的率定验证重叠。

M11／M12 使用真实 XAJ 加 Muskingum 前向计算和固定差分进化设置，仅搜索
两个指定参数，其余固定，目标评估不超过 128 次。连续状态在 split 边界
保持，场次状态独立。评分独立重放参数、目标值、锁参输出、评分样本及
指标，不要求参数唯一，也不要求真实观测达到某个高 NSE。

BMA 独立复算删失高斯分布、训练对数似然、成员源绑定、权重、均值与分位数、
非负输出和独立评价。允许可辨识性不足时的等效参数。图件检查真实解码、
尺寸、图层与科学元数据；报告检查受控结构化结论、指标排名、正文一致性
及相对路径和 SHA-256 证据绑定，不评价文风。

## 公开接口与隐藏评价

每题含 `task.json`、`generate_data.py`、`data/` 和 `expected/`。Agent 只收到
可见数据与裁剪后的 `task_public.json`。科学 DAG、核心能力清单、期望结果、
评分阈值、确认答案、隐藏 reference 与参考执行过程均不进入公开 JSON。
公开提示不点名 Skill、不规定执行顺序、不透露阻断真值。

两组均有 `/public/programs.json`、`PROGRAM_INTERFACES.md`、
`PROGRAM_DATA_CONTRACTS.json`、科学程序和基本
参数帮助；`OUTPUT_CONTRACTS.json` 定义通用的成果、决定与审查接口，不包含
逐题答案。`physical_calibration.py` 是两组共同可用的物理模型率定接口。
完整技能组另外挂载冻结的 41 个原子技能及 3 个 workflow。无技能组没有
这个挂载。外部原始资料、宿主技能目录、其他工作区及隐藏参考都不挂载。

`composite_contract_check` 返回全关键闸门判定，`scientific_invariant` 提供
独立科学检查。原有加权分数保留为诊断；不能用阈值替代成功判定。
新增结果字段为 `task_success`、`critical_errors`、`confirmation_results`、
`assessability`。缺少结果或科学证据会失败／不可判定，不能解释为科学正确。
关键错误仅在错误判据有足够证据时计入；一题多个错误在主指标中只计一题。

## 自动确认

Agent 使用两组共同的 `/public/confirm_user.py` 提出对象、字段和具体问题，
可一次询问多个事项。答案由宿主端的确定性字段／别名匹配返回，不使用
模型。未知字段只返回接口说明，不提示尚未询问的必要项。

答案表在容器外，宿主记录请求、响应、匹配答案、时间和关键成果第一次
出现的时间。正确确认要求问题匹配、答案先于相关成果产生、并落实到配置
与成果。重复询问不重复计分。“无法确认”“不授权修复”必须落实限制或
停止。科学决策时点以宿主可观察的相关成果为证据；不能据此声称识别任意
内部推理的真实时点。候选自己填写的确认文件不能替代宿主记录。

## 固定实验与预算

正式实验为 24 × 2 条件 × 3 CLI × 3 重复 = 432 次，按任务配对、固定种子
20261004 随机任务顺序并交替条件先后，串行执行。每个 CLI 内比较技能条件；
不同模型的 CLI 分别报告。每 CLI 每条件每轮 24 次，三轮合计 72 次。

两组固定镜像摘要、程序哈希、公开提示、基础模型、推理设置、用户答案、
资源和会话初始化。新容器与新会话禁用跨任务记忆及外部检索。公共提供商
配置必须单独审查，不能带 Skills、指令、记忆、回退模型或外部检索入口。
公共配置目录只允许选定的提供商配置和凭据文件，同时冻结整个目录及各 CLI
子目录的哈希，避免环境变量文件漂移；不允许放入答案表或其他资料。当前
配置模板故意保留未认证状态，实际预检通过后才可冻结。

普通题 900 秒，率定题 1,800 秒；4 CPU、8 GB 内存、最多 60 个规范化 Agent
工作单元与 120 次工具调用。确认 HTTP 请求计入工具预算；一次多字段
询问按一次确认请求计。CLI 启动、工具结果、重复事件不重复计数；当前
事件规则需要逐版本真实审计后认证，未知且无法去重的事件不接受正式运行。
适配器自测使用录制格式与假进程验证预算、超时、退出和日志。

正式启动失败单列并排除主指标分母；开始执行后的超时／预算耗尽算任务
失败。重跑必须整个配对重跑，原始尝试保留。报告选取最后一个完整配对，
未完成尝试单列。运行元数据冻结镜像、CLI、配置、公共程序、技能快照、
启动提示、任务和 lock 的哈希，阻止比较不同控制项的结果。

## 三项主指标

| 指标 | 分子 | 分母 |
|---|---|---|
| 任务成功率 | 全必需科学步骤、成果及确认闸门通过的运行数 | 纳入评测的任务运行数 |
| 关键科学错误率 | 至少一种有证据关键错误的运行数 | 纳入评测的任务运行数 |
| 必要信息确认率 | 正确确认并落实的信息项数 | 预设必要信息项总数 |

报告同时列出计数、比例、不可判定数／比例、重复波动，按 8／12／4 类别
及正常／阻断分别统计。配对差异为完整技能组减无技能组；bootstrap 按任务
聚类，保留同题重复，并按信息项数计算确认差异。成功率越高越好，错误率
越低越好。原子任务与组合任务的覆盖分别计算。

## 开发验收及正式入口

```powershell
conda activate HydroTune-eval
python -m harness.cli validate --suite atomic
python -m harness.cli validate --suite composite
python -m harness.cli validate --suite all
python scripts/verify_composite_tasks.py
python scripts/check_composite_repeatability.py
python -m pytest -q
python -m harness.experiment --output results/composite-schedule
```

最后一条仅生成 432 次运行的固定调度表，不启动 Agent。默认 suite 仍为
`atomic`。组合开发规则见[独立开发约束](../composite_tests/DEVELOPMENT_RULES.md)。

正式配置以 `runtime/experiment.template.json` 为模板，实际构建镜像并记录
digest，审查容器外公共提供商配置，完成模型／推理冻结、网络隔离和事件
审计，随后记录程序、技能与配置哈希。不要直接把认证字段改为 true 来
绕过验收。正式调用形态如下，此次开发没有执行：

```powershell
python -m harness.experiment --lock runtime/experiment.frozen.json --output results/formal --execute
python -m harness.experiment --lock runtime/experiment.frozen.json --output results/formal --report-only
```

指定 `--pair-id <配对ID> --attempt 2 --execute` 会重跑该配对两组。全部记录
留在输出目录，生成 `scientific_report.json`。正式前需解决当前运行环境
receipt 中的未完成项；容器构建文件及假进程测试不代替这一验收。
